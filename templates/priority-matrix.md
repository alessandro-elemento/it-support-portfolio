# Priority Matrix

Priority is worked out from two questions:

- **Impact:** how many people or how much of the business is affected?
- **Urgency:** how quickly does it need fixing?

This is a common service desk approach. Real organisations define their own levels and
response times, so treat the values below as the rules I use in this portfolio, not an
official standard.

| | Urgency: High | Urgency: Medium | Urgency: Low |
|---|---|---|---|
| **Impact: High** | P1 | P2 | P3 |
| **Impact: Medium** | P2 | P3 | P4 |
| **Impact: Low** | P3 | P4 | P4 |

## What the levels mean here

| Priority | Meaning | Example |
|---|---|---|
| P1 | Critical: many users or a core service are down | Email is down for the whole company |
| P2 | High: a serious problem for one team, or a key person cannot work | A team cannot open a shared drive |
| P3 | Normal: one user affected, with a workaround or no deadline | One user cannot print |
| P4 | Low: minor, cosmetic or a request | A user wants a shortcut added |

## Rules of thumb

- Treat anything involving a possible security incident (for example, a user reporting a
  suspicious email or account activity they did not do) as a reason to escalate to the
  security team, whatever the priority score says.
- Re-rate a ticket if you learn more. A "slow computer" can turn out to be a spreading problem.
- Always record why you chose the impact and urgency, not only the result.
